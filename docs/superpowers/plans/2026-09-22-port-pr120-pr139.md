# Port upstream PRs 120 and 139 Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Track RED/GREEN evidence below.

**Goal:** Recover orphan identities without stealing another worker's identity, and accurately report paused or pending PTY delivery.

**Architecture:** Adapt the useful upstream changes to the fork's existing recovery and gate ownership helpers. Preserve PID namespace checks and the 60-second stalled marker. Keep tests in the existing sibling test files.

**Tech Stack:** Rust 1.88+, rusqlite, vt100; no new dependencies.

**Design basis:** Review in this conversation; user explicitly requested planning and application, then waived agent-ops and a separate spec. Execute in the current clean feature branch. No board, additional worktree, or separate spec required.

## Global Constraints

- Source PRs: https://github.com/aannoo/hcom/pull/120 (8c834e3), https://github.com/aannoo/hcom/pull/139 (594b240).
- PR 122 (Droid attestation) is excluded, as agreed in the review recommendation.
- Preserve delivery safety: do not inject over real drafts or approval prompts.
- Never reclaim a row on session ID alone when another live or unknown-liveness PID owns it. Preserve PID namespaces.
- Do not rename the caller's pane when recovering another PTY. Rebind in the current session may refresh its own title.
- Report recovery failures before removing pidfile metadata or claiming success.
- Reuse conditional status clearing and stalled escalation; do not wholesale replace the delivery loop.
- Keep commits local; no publication or remote merge.

## Review Focus

- Matching session ID with a different live worker must not steal its row.
- Recovery from a separate management pane must not emit a title change for that pane.
- A hook updating status between a gate read and write must win over gate publication.
- A successful send with older unread messages must not be described as delivered merely because the status looks healthy.
- A narrow Antigravity terminal must distinguish the banner from a real draft extending its text.

### Decisions and environment

- Feedback reports current pending state immediately instead of adding upstream's 75ms polling window. Pending is normally expected immediately after an asynchronous PTY send, even for a healthy listening recipient; it is successful queueing, not a delivery error. No claim of synchronous receipt is made.
- Recovery rejects conflicting process/session owners conservatively. This may require resolving stale binding metadata before recovering, but never silently takes another live worker's session.
- Recovery exposes a fallible lifecycle status transition while preserving the existing best-effort wrapper for other callers. This prevents a swallowed status-write failure from deleting recovery metadata.
- `CODEX_HOME` inherited from the live agent caused the existing Codex setup test to target the real config directory; final tests remove this variable for the test process. The initial sandboxed full run also had 20 localhost-socket permission failures; the final suite ran with socket access and passed. These were environment restrictions, not test exclusions.
- No agent-ops board, separate spec, worktree, new dependency, remote push, or PR 122 integration. The initial independent review findings were resolved; the subsequent Bela review and per-finding responses are recorded in docs/superpowers/reviews/2026-09-23-port-pr120-pr139-review.md.
